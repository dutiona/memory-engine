[High] `init_schema()` still says to "set `schema_version=2`" before `migrate()`. If that write is unconditional on an existing v1 database, the engine will skip the v1→v2 migration and leave a mislabeled schema without `scopes` / `scope_id` columns. The plan needs to state explicitly that `init_schema()` only seeds `schema_version` for a fresh DB, for example via `INSERT OR IGNORE` or an existence check.

[Medium] Async verification is still incomplete. Because `async_engine.rs` is behind `#[cfg(feature = "async")]`, the current verification commands (`cargo test`, `cargo clippy --all-targets`, `cargo doc --no-deps`) do not guarantee the async API is compiled, linted, or tested. The plan should require `--features async` or `--all-features` for test/clippy/doc coverage.

[Low] Root-scope handling is still semantically inconsistent. `add_fact()` special-cases the string `"root"` to `scope_id=1`, but the rest of the API is described as path-based and `ScopeTree::resolve_path("root")` / `ResumeConfig { scope_path: Some("root".into()) }` / `ScopeQuery::Exact("root".into())` are not defined to behave the same way. Either reserve `"root"` everywhere or make `None` the only root selector and remove the string sentinel.
