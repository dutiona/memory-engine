### 1. MEMORY ARCHITECTURE: The Fallacy of the Primary Store
The assumption that one must choose between Memori (FTS5+Vector) and a Knowledge Graph (KG) as a "primary" entry point is a performance trap. KGs are notoriously high-latency for initial retrieval; they are "reasoning" structures, not "search" structures. You must implement a **Tri-Store Entity-Linked Retrieval** architecture. Memori remains the high-speed (43us) "Hot Cache" and initial entry point via hybrid FTS5/Vector search. However, the vector hit should not return just text; it must return a **Symbolic UID** that triggers a graph traversal in `SurrealDB` or `EdgeDB`. This composition treats the KG as a *Latent Relational Map* that expands the context window based on topological proximity, while Memori handles the semantic fuzziness. Search is the entry; the Graph is the context expander.

### 2. BUILD vs COMPOSE: Modular Orchestration vs. Monolithic Debt
Forking Panther is an admission of architectural defeat; you inherit a daemon-centric model that may not align with ZeroClaw’s trait-driven agility. Conversely, building from scratch is "Not Invented Here" syndrome. The adversarial path is to build a **Service-Oriented Orchestrator** that treats Panther’s 9 crates as *pluggable libraries* rather than a base. Use `ZeroClaw` to define the agentic "Traits" (the *behavioral* contract) and `Rig` for the *inference* contract. By extracting Panther’s MCP and Ollama connectors into a shared "Common Interface" crate, you avoid inherited debt while leveraging solved connectivity. This "Crate-First" approach allows the Mac Mini M4 to run the core logic while delegating specialized "Specialist" tasks to the Jetson via IPC.

### 3. MLX vs OLLAMA: The Distributed Inference Hybrid
Choosing between MLX and Ollama is a false dichotomy that ignores your heterogeneous hardware. MLX is non-negotiable for the **Reasoning Backbone** (Qwen 3.5 35B) on the M4 to maintain the ~50 tok/s "speed of thought" required for autonomous loops. However, Ollama should be relegated to the **Worker Nodes** (Jetson Orin and Main PC). This creates a **Hierarchical Inference Bus**: the M4 handles the "System 2" reasoning via MLX, while the Jetson runs Ollama for "System 1" tasks like embedding generation, summarization, or vision-language processing (LLaVA). Use a Rust-native proxy that implements the OpenAI API spec, masking the backend and allowing for seamless failover if the MLX model hits RAM limits.

### 4. NIGHTLY MEMORY MODEL: Consolidation, Not Fine-Tuning
The user's demand for nightly fine-tuning is an anti-pattern that risks **Catastrophic Forgetting** and model collapse. Weight updates are too blunt for a "brain model." Instead, use the 4090 for a **Nightly Consolidation Cycle** (Dreaming). This phase shouldn't fine-tune the LLM, but rather fine-tune a **PEFT/LoRA Retrieval Reranker** (like a BGE-CrossEncoder). Use the 4090 to batch-process the day's SQLite logs, converting unstructured Memori chunks into structured KG triples and "Case Files" for Memento. The "Brain" stays frozen and reliable; the *Retrieval Weights* and *Knowledge Graph* evolve. This mimics human sleep cycles—reorganizing metadata and strengthening synaptic (graph) links without altering the base reasoning capabilities of Qwen.

### 5. AUTONOMY & HITL: The Asynchronous Escalation Bus
Blocking on a human response is the death of autonomy. The "Human-in-the-Loop" (HITL) must be treated as an **Asynchronous Oracle**. Implement an **Escalation Work-Queue** abstraction: when the agent hits a ToS-restricted task (e.g., needing Claude’s reasoning), it must not wait. It drafts the "Oracle Prompt," pushes it to a Telegram/Discord bus via Panther, and marks that task branch as `PENDING_EXTERNAL`. The agent then **context-switches** to parallel sub-tasks that are within its local capability. To prevent total divergence, use the local Qwen model to "hallucinate" a predicted Oracle response; if the actual human response contradicts the prediction, the agent performs a **State Rollback** and re-plans. This ensures the 32GB M4 is never idle.
