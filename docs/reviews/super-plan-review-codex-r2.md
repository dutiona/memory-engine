[High] Derived-entity scoping is still not fully resolved. The invariants now define how events, edges, summaries, consolidation, forgetting, and conflict resolution must propagate `scope_id`, but the task bodies do not actually wire that behavior through the internal modules. In Task 7 Step 3, `consolidate()` and `forget()` still call scope-agnostic internals, and there is no explicit task to update consolidation/conflict/ingest code so newly created summaries and edges get the correct scope. This leaves the core scoping contract only partially implemented.

[Medium] The migration test plan is still inconsistent with the new “fresh DB creates latest schema directly” semantics. Task 1 Step 1 expects `init_schema()` to leave `schema_version=1`, but Task 1 Step 3 and the migration contract now say `init_schema()` creates v2 and sets `schema_version=2`. As written, `migrate_from_v1_runs_without_error` no longer exercises a real v1→v2 path. You need an explicit legacy-schema fixture/helper for migration coverage.

[Medium] The async API lost parity with the scoped sync API. Task 7 Step 5b adds `scope: Option<&str>` to `ingest`, `consolidate`, and `forget`, but Task 8 still sketches async methods without those scope parameters. That reintroduces an isolation gap for async consumers.

[Medium] The connection initialization contract is still internally inconsistent for in-memory engines. The contract says all connections go through `open_connection()` so required PRAGMAs are always applied, but Task 6 `open_memory()` still constructs its connection via `open_memory()` directly. Unless that helper is guaranteed to apply the same initialization, tests and in-memory behavior can drift from file-backed behavior.

[Medium] Task 5 introduces a new SQLite capability dependency via `json_each(?3)` without stating it as a requirement or providing a fallback. If the build uses a system SQLite without JSON support, scoped search breaks at runtime. The plan should either require JSON-enabled SQLite explicitly or use dynamically expanded `IN (?, ?, ?)` placeholders instead.

[Low] The ScopeTree efficiency fix regresses in Task 7. The changelog says the prior reload issue was fixed with surgical `ScopeTree::insert()`, but Task 7 `add_fact()` switches back to `ScopeTree::load(conn)?` after scope creation. That is not a correctness bug, but it contradicts the stated resolution and adds unnecessary reload cost.
