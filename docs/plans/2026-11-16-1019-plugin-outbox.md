# feat(plugin): queue every Claude Code lifecycle event in a local outbox and deliver it (#1019)

Implementation plan for dutiona/memory-engine#1019 (umbrella dutiona/infra#37). The contract is ADR-0020 (§3, §4,
§5, §10, §11, §12), which wins over any restatement in the issue. Synthesized from three lens drafts (mvp-first,
risk-first, architecture-first); the rationale is in the closing section.

## Outcome

Installed from the repository's marketplace as `memory-engine@memory-engine`, the plugin registers the ten hooks of
ADR-0020 §11 as synchronous exec-form hooks running one POSIX sh helper, `bin/me-hook`. Each hook writes the hook
input byte for byte, plus a curl header file carrying the envelope, into `~/.local/state/memory-engine/outbox/`,
publishes the event with one rename, records the endpoint, publishes a stable copy of the helper, starts a detached
flush and exits 0, within a measured p95 of 50 ms. The flush delivers oldest first under a lock, with ADR-0020 §3's
total reaction table, and hands the token to `curl` on its standard input. `env -i /bin/sh
~/.local/state/memory-engine/bin/me-hook flush` (the watcher's call) delivers to the recorded endpoint. A shell suite
passes on dash and on macOS `/bin/sh` (bash 3.2), and a scripted `claude -p` run against a local stub proves capture
across teardown and exactly-once delivery, before the server half exists.

## Design (shared by every item)

**D1. Argv contract.** The helper is always run by a shell, never executed directly, so it needs no exec bit:

| Call | stdin | stdout | exit |
|---|---|---|---|
| `me-hook capture <me_url> <dev_root>` | the hook input | nothing | 0, always |
| `me-hook session-start <me_url> <dev_root>` | the hook input | the D9 line, or nothing | 0, always |
| `me-hook flush` | not read | nothing | 0; 1 with one stderr line only when no state root can be found (D6) |
| anything else | not read | nothing | 1, one usage line on stderr (never 2, which blocks a prompt or a stop) |

An argument that is empty or starts with `${user_config.` counts as unset, which covers both ways an unset option might
be passed. `me_url` is used only when it matches `http://?*` or `https://?*` and every byte is in 0x21–0x7E (one
trailing `/` dropped). `dev_root` is sent only when it starts with `/` and every byte is in 0x21–0x7E other than `"`,
`%` and `\`. Anything else is ignored and the event is still queued.

**D2. Registration** (`hooks/hooks.json`). Each of the ten §11 events has exactly one matcher-less group with one
handler, `{"type":"command","command":"/bin/sh","args":["${CLAUDE_PLUGIN_ROOT}/bin/me-hook","<sub>","${user_config.me_url}","${user_config.dev_root}"],"timeout":5}`,
where `<sub>` is `session-start` for `SessionStart` and `capture` for the nine others. No `async`, no `asyncRewake`.
Exec form is required because only exec form substitutes `${user_config.*}`. `bin/` is a Claude Code component
directory whose files are on the Bash tool's PATH while the plugin is enabled: `bin/me-hook` is committed as mode
100644, so a PATH lookup skips it and the model cannot run it as a bare command; Verification asserts the mode with
`git ls-files -s`. Plugins with a `bin/` are not installed by claude.ai or Cowork; the README says so (Q6).

**D3. Process rules.** First statements: `LC_ALL=C; export LC_ALL`, `umask 077` (directories 0700, files 0600, since
`chmod` is not an allowed utility), `unset GIT_DIR GIT_WORK_TREE`, `ME_VERSION=0.1.0`. PATH is inherited, except
under D6's `$0` rule (the stable copy, which is what the watcher runs), where it is set to `/usr/bin:/bin` and
exported unconditionally: under `env -i` the shell supplies its compiled-in default, which on macos-mini's bash 3.2
is `/usr/gnu/bin:/usr/local/bin:/bin:/usr/bin:.` (probed 2026-11-16), so a `curl` in the working directory would run. No `set -e`/`set -u`, no `local`, `[[`, arrays, `$'…'`, `echo -e`, no `case` inside `$( )` (bash 3.2
misparses it). External commands: only `mkdir mv rm cat date git curl`, plus `/bin/sh` for the detached flush. Values
pass through globals, not subshells, so the hot path forks only for external commands.

**D4. On-disk contract** (versionless; under `S=~/.local/state/memory-engine/`, `O=$S/outbox`):

| Path | Content |
|---|---|
| `S/bin/me-hook` | the stable helper copy |
| `O/<id>/body`, `O/<id>/headers` | one queued event, published by one `mv` of `O/tmp/<pid>/` |
| `O/rejected/<id>/` | a parked event, same shape, kept for ever |
| `O/endpoint` | one line: the base URL, replaced by rename only when it changes |
| `O/seq/<epoch>.<n>/` | one seq reservation (§12), pruned after an hour |
| `O/tmp/<pid>[.<what>]` | an event, endpoint, helper copy or lock being prepared; every name starts with the writer's pid |
| `O/lock/owner`, `O/lock/<pid>.stamp` | `<pid> <epoch>` of the one flusher, written once; its renewal stamps (D8) |

`<id>` is `<10-digit epoch>-<6-digit seq>-<pid>`. Only event directories start with a digit, so under `LC_ALL=C` the
glob `"$O"/[0-9]*` lists the queue in order-key order. `headers` holds one LF-terminated `Name: value` line per header,
in this order, an absent fact omitted, never `Authorization`: `ME-Event-Id`, `ME-Event-Time`, `ME-Event-Seq`,
`ME-Harness: claude-code`, `ME-Client-Version`, `ME-Project-Root`, `ME-Project-Dev-Root`, `ME-Project-Upstream-Url`,
`ME-Project-Origin-Url`, `ME-Project-Branch`. A flusher never reads or rewrites `headers`. Replaying a parked event is
`mv O/rejected/<id> O/`. #1030's counts are the matches of `O/[0-9]*` and `O/rejected/[0-9]*`.

**D5. Capture sequence** (`capture` and `session-start`; every failure removes `O/tmp/$$` and exits 0, stderr to
`/dev/null`):

1. `rm -rf O/tmp/$$` only if it exists (a reused pid), then `mkdir O/tmp/$$`. **Heal rule**, used here and at every
   later step that writes into a directory of D4 (`O/tmp`, `O/seq`, `O/rejected`, `S/bin`): when the step fails, run
   one `mkdir -p` of all four, then retry that step once. The common path costs no `mkdir -p`, and any directory
   deleted on its own (a user "cleaning tmp") heals at the step that needs it. The rule never applies to step 4,
   which consumes stdin: a retried `cat` would read only the rest of the input.
2. Record the endpoint when `me_url` is valid (D1) and differs from the line `read` from `O/endpoint`:
   `O/tmp/$$.endpoint`, then `mv`. **Best effort**: a failure here (after the heal rule) does not abandon the event,
   but it removes `O/endpoint` (`rm -f`), so no flush can deliver this event, or its token, to the previous URL; a
   missing or unreadable endpoint holds every flush until a later hook records the new one. A flusher already
   running re-reads `O/endpoint` before each request (D8), so it stops too. Accepted, as a consequence of the per-machine
   endpoint the issue requires: while sessions started before a change of `me_url` still run, the recorded endpoint is
   whichever URL was written last, and queued events go there; both URLs are ones the owner configured, with the same
   machine token, and the README says to restart running sessions after changing `me_url`. If the `rm` fails as well, `O` itself is
   not writable, and step 7's publication, an `mv` into `O`, fails the same way: nothing is queued or sent.
   It happens before the event is published, so a flusher that sees the event also sees the endpoint. Accepted
   residual: a flusher that read "no endpoint" (events queued while `me_url` was unset) just before this write holds
   without a second look, while this hook's own flush finds the lock taken; the new event then waits for the next
   hook or the watcher — a delay, not a loss, consistent with §12's no second look after a hold.
3. Derive the facts (D7) before the body, so only builtins and one `mv` separate the time from the publication.
4. `cat > O/tmp/$$/body`. A failure here abandons the event (no retry, see the heal rule).
5. One `date -u '+%s %Y-%m-%dT%H:%M:%SZ'`, split by parameter expansion: the epoch and `ME-Event-Time` (§12).
6. Seq, exactly as §12 says: `mkdir O/seq/<epoch>.<n>` for n = 0, 1, …; the first success for which neither `O/<id>`
   nor `O/rejected/<id>` exists is the seq (two builtin tests; a parked event with the same ID would otherwise be
   nested by a later replay). An existing `O/<id>` is a collision and n moves on: `mv` onto an existing directory would nest the
   event inside it and succeed; no live process can create `O/<id>` concurrently, because `<id>` ends with this hook's
   own pid. The loop is bounded at n = 1000 (only 1,000 events reserved in one second could reach it); reaching it, or
   a `mkdir` failure that leaves the path absent after the heal rule, abandons the event. The 6-digit form is
   `s=000000$n; ${s#"${s%??????}"}`, no fork. Reservations older than an hour are pruned (D8); what that means for a
   clock stepped back by more than an hour is Q7.
7. Write `headers` with one redirected group of `printf` builtins, then `mv O/tmp/$$ O/<id>`.
8. Publish the stable copy, **best effort** (after publication, so a failure never costs the event):
   `cat "$0" > O/tmp/$$.me-hook && mv O/tmp/$$.me-hook S/bin/me-hook`.
9. `session-start` only: D9.
10. `/bin/sh "$0" flush </dev/null >/dev/null 2>&1 &` — a new process rather than a subshell, so the flusher's `$$`
    is its own pid and the lock never names a parent that exits at once.

**D6. State root.** When `$0` ends in `/.local/state/memory-engine/bin/me-hook`, `S=${0%/bin/me-hook}` and
`H=${S%/.local/state/memory-engine}`; otherwise `H=$HOME` and `S=$H/.local/state/memory-engine`. With neither, the
capture subcommands exit 0 silently and `flush` exits 1 with `me-hook: no HOME and not run as the stable copy`. The
token file is `$H/.config/memory-engine/secrets/token`. XDG variables are ignored, so hooks and the watcher always
agree on the paths. The watcher's `env -i /bin/sh <stable> flush` therefore needs no HOME, PATH or argument.

**D7. Project facts** (channel-neutral functions, reused by #1028's helper mode and #1030's read). Inputs: only
`D=$CLAUDE_PROJECT_DIR`, never the working directory or the input's `cwd`. When `D` is empty, holds a line feed, or is
not a directory, there is no project fact at all (the dev root is withheld too). Every git call is
`git -C "$D" … </dev/null 2>/dev/null` (the facts are derived before `cat` reads the hook input, so no git call may
touch stdin):

- `git rev-parse --path-format=absolute --git-dir --git-common-dir --show-toplevel` (one call). Failure: Root is
  `D`, no other git call. Otherwise, in order:
  1. the git dir equals the common dir (the session is in the repository's main, or only, working tree: an ordinary
     clone, a submodule checkout, the main tree of a `--separate-git-dir` repository): Root is the top level, which is
     that main tree (tested first, so a separate git dir whose path happens to end in `/.git` is never taken for a
     working tree);
  2. a linked worktree whose common dir ends in `/.git`: Root is the common dir minus `/.git`, the main working tree,
     which every linked worktree shares. Two rarer layouts also land here: a bare repository cloned as `proj/.git`
     (the usual bare-worktree setup), whose worktrees all send the container `proj/`; and a `--separate-git-dir`
     repository whose git dir is itself named `.git`, whose linked worktrees send the git dir's parent while its main
     tree sends its own top level (case 1). Git cannot tell either from an ordinary clone (`git worktree list` also
     reports that parent first, probed 2026-11-16); Q8 covers both;
  3. otherwise (a linked worktree of a `--separate-git-dir` or bare repository whose git dir is not named `.git`, or
     of a submodule): git records no
     main working tree that a linked worktree can name — probed 2026-11-16 on git 2.53: `git worktree list
     --porcelain` reports the git dir as the first worktree — so Root is the top level of this worktree. Q8 asks
     whether that ADR gap is acceptable as stated.
- Branch: `git symbolic-ref -q HEAD` minus `refs/heads/`; absent when detached (`--short` is avoided: it prints
  `heads/x` when a tag shares the name).
- Remotes: `git remote get-url upstream`, then `origin`, each through `strip_userinfo`: with `://`, drop through the
  last `@` of the authority (the text up to the first `/` after `://`); without `://`, when the text before the first
  `:` holds no `/` (scp form), drop through the last `@` of that text; anything else unchanged.
- `pct`: a value whose bytes are all in 0x21–0x7E and none of `%`, `"`, `\` is used as is, no fork. Otherwise walk it
  one byte at a time with `r=${s#?}; c=${s%"$r"}` under `LC_ALL=C`: space, `%`, `"` and `\` map to `%20 %25 %22 %5C` by
  `case`; any other byte outside 0x21–0x7E becomes `h=$(printf %02X "'$c")`, written as `%${h#"${h%??}"}` (the last
  two hex digits). Probed on 2026-11-16: macos-mini's bash 3.2 prints `FFFFFFFFFFFFFFC3` for `printf %02X "'<0xC3>"`
  (signed char) where dash, bash 5 and busybox print `C3`; keeping the last two digits gives `%C3%A9` on all four.

**D8. Delivery.**

- The request, exact (`$ev` an event directory, `$url` the endpoint):
  `printf 'Authorization: Bearer %s\n' "$tok" | curl -q -g -s --noproxy '*' -o /dev/null -w '%{http_code}' --connect-timeout 5 --speed-limit 8192 --speed-time 60 -H @- -H "@$ev/headers" --data-binary "@$ev/body" "$url/lifecycle/events"`.
  `-q` first makes curl skip `~/.curlrc`; there is no `-L`. `-g` stops curl globbing `[]{}`, so an IPv6-literal URL
  works. `--noproxy '*'` sends the Bearer line to the server and to no proxy, and makes a hook's flush and the
  watcher's `env -i` flush take the same route (Q5). A non-zero curl exit is `000` whatever it printed. At the
  8192 B/s floor, 16 MiB takes at most 2,048 s, inside the lock's hour; a 60 s stall aborts (the server's 408 is 60 s).
  The token is read with `tok=; IFS= read -r tok < "$TOKEN" || [ -n "$tok" ]` (POSIX `read` returns non-zero on a
  last line without LF but still assigns it; both file forms ADR-0020 §4 allows are accepted, an empty one is a hold)
  and leaves only through the `printf` builtin into the pipe: never exported, never an argv, never under `S`.
- Reactions on the code alone: `204` → `rm -rf "$ev"`, next event; `400|409|413|422` → `mv "$ev" "$O/rejected/${ev##*/}"` (the full target name: with a bare
  `"$O/rejected/"`, a deleted `rejected/` would make rename(2) turn the event itself into `rejected/`, exit 0; the
  full name fails instead, so D5's heal rule recreates it and the park is retried once), next event; anything else → stop with the queue intact. "Anything else" is both ADR classes, retry (408, 429, 5xx,
  `000`) and hold (401, 403, 1xx, other 2xx, 3xx, other 4xx): in this ticket both end the flush with every event
  queued; they differ only in what #1030's status line reports. A one-line comment says so.
- `flush`: return 0 when `O` is missing. Loop: take the lock or return 0; prune; read the endpoint and the token (a
  missing one is a hold); drain `"$O"/[0-9]*` in glob order, renewing the lock before each request and re-reading `O/endpoint` with the
  `read` builtin (a value other than the one this flush started with, or none, is a hold: stop, so a URL that changed
  or was withdrawn mid-flush never receives another event or token; the window between that read and the request is
  the same one-request residual as the lock's); release; on a stop
  return 0; otherwise look once more and loop when an event is there.
- **Lock.** The lock is the directory `O/lock`. It holds `owner` = `<pid> <epoch>`, written once, before the lock is
  published, and never rewritten by anyone; renewals go to a separate per-flusher file `<pid>.stamp`.
  - Acquire: `mkdir O/tmp/$$.lock`, write `owner` into it, `mv O/tmp/$$.lock O/lock`; the lock is held exactly when
    `O/lock/owner` then reads back as that record. A failed `mv`, or one that moved the directory inside an existing
    lock, means not held: remove `O/tmp/$$.lock` and `O/lock/$$.lock`, then judge the owner.
  - Stamp: the newer of `owner`'s epoch and the content of `O/lock/<owner pid>.stamp` when that file reads as digits.
  - Stale exactly when `owner` is not two digit strings, or `kill -0 <pid>` fails, or now − stamp > 3600. Because the
    lock is published whole, a live lock always has its record, so an unreadable or malformed `owner` is stale at
    once, even with a live pid: no live writer of this protocol leaves one (that is how §12's "neither can be read"
    is applied).
  - Break: remove a leftover `O/tmp/$$.stale`, then `mv O/lock O/tmp/$$.stale` (one rename: of several breakers of
    one directory exactly one succeeds), `rm -rf O/tmp/$$.stale`, then acquire once more; a second failure, or a live
    owner, ends the flush.
  - Check, before each request and before release: `O/lock/owner` reads as this flusher's record; anything else
    stops the flush at once.
  - Renew, after a passing check and before the request: write `O/tmp/$$.stamp` with `now`, then
    `mv O/tmp/$$.stamp O/lock/$$.stamp`. If another flusher replaced `O/lock` between the check and this `mv`, the
    stamp lands in the replacement under this flusher's own name, which the replacement's owner never reads: no
    flusher ever writes another flusher's record or stamp.
  - Release: after a passing check, `rm -rf O/lock`.
  - What holds, and what the tests drive: an `owner` record, once published, names its flusher until that lock is
    removed, so at any instant at most one flusher passes a check. The check and the action after it are not atomic
    with these utilities, so a flusher displaced between its check and its request sends that one request and stops
    at its next check; a releaser can remove a lock taken a moment after its check, whose flusher then stops at its
    next check, while the releaser, having released on an empty queue, makes the second look and drains anything the
    displaced flusher left. Accepted residual (§12 "best effort, which §5 makes safe"): at most one duplicate request
    per interleaving, answered `duplicate` by the server. No event is lost: an event leaves the queue only by its own
    204 or park.
- **Prune**, under the lock on each pass, one `rm -rf` of what it collects: `O/tmp/<pid>*` whose pid fails `kill -0`
  (a hook killed mid-write leaves an unredacted body there), and `O/seq/<epoch>.*` with epoch more than 3600 s before
  now (a capture is killed at its 5 s timeout, so no live reservation is that old). See Q7.

**D9. SessionStart line.** Before it publishes, `session-start` counts `O/[0-9]*` and `O/rejected/[0-9]*` with a
builtin `for` loop. After publishing, when the token file does not exist, it prints exactly
`{"systemMessage":"memory: no token file"}` when both counts are 0, else
`{"systemMessage":"memory: no token file; outbox <q> queued, <p> parked"}`, then a LF: fixed templates with integers
substituted, nothing escaped. With a token file it prints nothing (#1030 adds the read).

## Open questions for Michaël

1. **BLOCKING — the credential for `real-claude.sh` under a scratch HOME.** A scratch HOME answers `Not logged in`.
   Default: you run `claude setup-token` once (a browser sign-in that prints a long-lived token), keep it in your
   secret store, and export it as `CLAUDE_CODE_OAUTH_TOKEN` only in the shell that runs the script (or hand the
   orchestrator a 0600 file path outside the repository and outside `~/.claude`, which the worker exports for that one
   command). The script passes it to `claude` only through an environment built from nothing (`os.execve`), never in
   an argv or a file. Your credentials file
   is never read or copied (it is yours, and a refresh by a copy could rotate it). Alternative: an
   `ANTHROPIC_API_KEY`, handled the same way and billed per token. Items 3 and 7's real-run greens wait for it.
2. **DEFAULTED — the no-token line carries §10's outbox part when a count is not zero**
   (`memory: no token file; outbox 2 queued, 0 parked`). A bare line would break §10's grammar from the second
   session on.
3. **DEFAULTED — marketplace `memory-engine`, plugin id `memory-engine@memory-engine`.** dutiona/my-dotfiles#1911,
   #1028 and dutiona/infra#83 use that id; renaming later means a reinstall on every machine.
4. **DEFAULTED — macOS latency is reported, not gated**, because no ticket measures it. Recommendation: ask
   dutiona/infra#83 to measure the Mac too.
5. **DEFAULTED — the flush bypasses proxies (`--noproxy '*'`).** With an `http://` URL and a proxy in the hook's
   environment, the Bearer line would otherwise go to the proxy in clear, and a hook's flush and the watcher's `env -i`
   flush would take different routes. The cost: a machine that can reach the server only through a proxy cannot
   deliver; say so if one of yours does.
6. **DEFAULTED — the helper stays at `bin/me-hook`, as the issue names it.** `bin/` puts the plugin's files on the
   Bash tool's PATH (made harmless by committing the helper without its exec bit) and stops claude.ai and Cowork from
   installing the plugin. The alternative, `scripts/me-hook`, avoids both and changes the path #1028 and the issue
   use; the stable copy the watcher runs is unaffected either way.
7. **DECIDE AT APPROVAL — event-ID uniqueness after a backward clock step (a tension inside ADR-0020).** §3 says an
   ID is "unique per machine for ever"; §12 fixes how it is made: `mkdir <outbox>/seq/<epoch>.<n>` from n = 0, the
   epoch and header time from one `date` call. Reservations cannot be kept for ever (one directory per event), and
   once one is pruned, a clock stepped back past it can mint the same `<epoch>-<seq>-<pid>` again, if the same pid
   also recurs. Codex rejected both a residual and a client-side monotone counter (which changes §12's rule) without
   your decision. Options:
   - (a) **Recommended:** follow §12 literally, prune reservations older than an hour, and record the residual in
     ADR-0020 with a one-line amendment in this PR ("unique per machine for ever, unless the clock steps back by more
     than an hour and a pid recurs in the same second with the same seq"). Consequence: a re-minted ID is answered
     409 and parked (kept) when its body differs; when its body is byte-identical, it is answered `duplicate` and
     removed, so that second, distinct occurrence and its effects (a second final message, a second tool event) are
     not stored. Either needs a stepped-back clock and a pid collision at once.
   - (b) Never prune `seq/`: the ADR stays as written; `seq/` grows by one empty directory per event, for ever.
   - (c) A monotone (epoch, seq) counter from `seq/`'s high-water mark, with §12's seq and time rules amended (a
     stepped-back clock would report its last used second until it catches up). Not a ready design: revision 4's
     version still let a hook paused after its re-check have a live reservation pruned, and its bounded retry could
     abandon a capture; choosing it means a corrected design, reviewed again.
   The plan implements (a) unless you choose otherwise; (a)'s ADR line lands as its own `docs(adr)` commit.
8. **DECIDE AT APPROVAL — `ME-Project-Root` in a linked worktree of a `--separate-git-dir`, bare or submodule
   repository.** §3 asks for "the main working tree's root … so that linked worktrees share it". Git cannot name that
   tree from such a worktree. What the plan sends, by layout: a linked worktree of a bare repository cloned as
   `proj/.git` sends the container `proj/`, shared by all its worktrees (D7 case 2, a reasonable value); a linked
   worktree of a `--separate-git-dir` repository whose git dir is named `.git` sends that git dir's parent, which is
   not a working tree, while the main tree sends its own top level (cases 2 and 1); a linked worktree of a bare or
   separate git dir not named `.git`, or of a submodule, (D7 case 3) sends that worktree's own top level, so its project key differs
   from the main tree's. It matters only for a project with no remote (a path key), in a layout that is rare. The
   alternative is the common dir for every worktree of those layouts, the main tree included (D7 case 2 would change
   too): all worktrees then share one value, but it is not a working tree, and when the git dir sits outside the dev
   root ADR §7 derives no path key at all, so such a project without a remote lands in the machine's `unscoped`
   bucket. Recommended: the plan's
   rule, plus one sentence in ADR-0020 §3 naming the exception, in the same `docs(adr)` commit as Q7.
