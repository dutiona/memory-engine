# build(container): run build scripts and proc-macros without network (#1068)

## Outcome

The server image build gives network only to steps that run no crate code: the two `apt-get` steps (Debian-signed
packages) and `RUN cargo fetch --locked`, which downloads the locked crates and executes none of them. `cargo build`,
where every dependency's build script and proc-macro runs, and the runtime `--version` smoke, which runs the built
binaries, start with `RUN --network=none`; `--offline` turns anything the fetch missed into a build failure instead of
a download. The rule is written in the `Containerfile` header for the next editor and in the install guide, and the
image builds both from a clean checkout and from a `git archive` tar on stdin.

## Constraints

- The design is settled (decision M1 (a), approved by the owner 2026-11-17: "M1 I agree with rec."); not reopened.
- Builder stage, replacing `RUN cargo build --release --locked -p memory-engine-mcp -p memory-engine-cli`, verbatim:

  ```dockerfile
  # Network, fetch only: cargo fetch downloads the locked crates and runs none of their code.
  RUN cargo fetch --locked
  # No network: build scripts and proc-macros run here.
  RUN --network=none cargo build --release --locked --offline -p memory-engine-mcp -p memory-engine-cli
  ```

- Runtime smoke, verbatim:
  `RUN --network=none memory-engine-mcp --version && memory-engine-cli --version && sqlite3 --version && curl --version`
- "The `apt-get` steps keep the network: they install Debian-signed packages from the base image's own publisher."
- Each offline step is one line starting with `RUN --network=none ` (line-anchored checks downstream must match it).
- Both paths must build: `podman build --pull=newer` from a clean checkout, and
  `git archive --format=tar <ref> | podman build --pull=newer -t memory-engine:<tag> -`. `.containerignore` is
  unchanged; a tar context on stdin honors it (measured, podman 5.7.0: `COPY . .` saw only `Cargo.lock`, `Cargo.toml`
  and `crates/`).
- Public repository: no home paths, host names or private-infra detail in the plan, commits, PR or docs.
- Smallest change; no speculative abstraction; tests in proportion to risk, never asserting incidental output format;
  Conventional Commits; no co-author line on branch commits.
- Merge gate: the `AGENTS.md` Verify block, run locally; CI is never relied on.
- On the build machine every podman build and cargo command runs under `flock <heavy-job lock>` (one heavy job at a
  time), cargo with `CARGO_BUILD_JOBS=16`. Written below as `HEAVY=flock <lock>`. The host's `CARGO_BUILD_JOBS` does
  not reach the cargo inside an image build, so the verification builds add `--cpuset-cpus=0-15` (cargo sizes its
  jobs from the CPUs it may use); this bounds host load only and is not part of the documented command.
- PR body: `Closes #1068`, `Refs dutiona/infra#37`; classification Security patch; review gate Full (Default
  severity). The worker never merges.

Facts that retire the remaining risks: `Cargo.lock` has no git sources; no `rust-toolchain` file exists (and the
allowlist would drop one), so rustup downloads nothing offline; `cargo fetch` without `--target` downloads every
package the lock reaches, for every platform, into the image's `CARGO_HOME` (`/usr/local/cargo`), and nothing between
the two steps moves it; the exact change already built from an archive of 97c8e77 (exit 0, both `--version` lines).

## Documentation

The `Containerfile` header (item 1) and `## Server image` in `docs/getting-started/installation.md` (item 2) are the
only places the image build is documented. The existing bullets (`--pull=newer`, `--locked`, the allowlist, Podman
over Docker) stay true; the archive form inherits the allowlist (measured above). No changelog exists.

## Testing

No committed test. The property is a build step's network namespace, which only an image build exercises; no cargo
test can run one, and a test parsing `Containerfile` would check text, not isolation (#1044 verified its
`Containerfile` the same way). Item 1's static greps are the red; the evidence is behavioural and goes in the PR:
V1 shows `RUN --network=none` isolates on this builder, V2 shows the fetch covers the offline build on the production
path, V3 the documented checkout path, V4 both entry points of the final image. The cargo matrix (V5) guards against
regressions only: no Rust changes.

## Verification

From the worktree root, after item 2's commit, each command unpiped; logs go to a private scratch directory outside the
worktree (`$LOGS`), never committed.

- **V1, isolation probe** (not committed): a `Containerfile` in a new empty directory outside the worktree holding
  `FROM docker.io/library/debian:trixie-slim`, `RUN cat /proc/net/dev`, `RUN --network=none cat /proc/net/dev`; then
  `$HEAVY podman build --no-cache -t localhost/me1068-netprobe <dir> > $LOGS/netprobe.log 2>&1; echo "exit=$?"`.
  Expect `exit=0`; the first step lists `lo` and at least one other interface, the second only `lo`. Remove the probe
  image after. The PR reports only "networked step: `lo` + N other interfaces; offline step: `lo` only", never the
  interface names or counters (a rootless tap device can carry the host's interface name).
- **V2, production path, fresh** (the PR's measured evidence):

  ```bash
  git status --porcelain -- Containerfile .containerignore Cargo.toml Cargo.lock crates   # prints nothing
  $HEAVY bash -o pipefail -c 'git archive --format=tar HEAD | podman build --pull=newer --no-cache --cpuset-cpus=0-15 -t localhost/memory-engine:1068-archive -' > $LOGS/archive.log 2>&1; echo "exit=$?"
  grep -nE 'STEP [0-9]+/[0-9]+: RUN|Finished|^memory-engine-(mcp|cli) ' $LOGS/archive.log
  ```

  Expect `exit=0`; in order: the `RUN cargo fetch --locked` step, the `RUN --network=none cargo build` step, cargo's
  `Finished` line, the `RUN --network=none memory-engine-mcp --version` step, then one `memory-engine-mcp <version>`
  and one `memory-engine-cli <version>` line (the PR quotes the actual output). `--no-cache` keeps the earlier 97c8e77
  build's layers from standing in for this run.
- **V3, clean checkout:** `git status --porcelain --ignored -- Cargo.toml Cargo.lock crates` prints nothing (a
  `target/` entry is harmless: `.containerignore` excludes `**/target`; anything else is a dirty context, fix first),
  then `$HEAVY podman build --pull=newer --cpuset-cpus=0-15 -t localhost/memory-engine:1068-checkout . >
  $LOGS/checkout.log 2>&1; echo "exit=$?"` exits 0 (cache hits from V2 are fine: the smoke is a build step, so
  `exit=0` still means both binaries answered).
- **V4, entry points:** `podman run --rm localhost/memory-engine:1068-archive --version` prints one
  `memory-engine-mcp <version>` line; `podman run --rm --entrypoint memory-engine-cli
  localhost/memory-engine:1068-archive --version` prints one `memory-engine-cli <version>` line.
- **V5, merge gate:** each cargo line of the `AGENTS.md` Verify block in order, as
  `$HEAVY env CARGO_BUILD_JOBS=16 <line> > $LOGS/gate-<n>.log 2>&1; echo "exit=$?"`, the two `cargo doc` lines with
  `RUSTDOCFLAGS="-D rustdoc::broken_intra_doc_links -D rustdoc::private_intra_doc_links"`. Expect every `exit=0` and
  `git status --porcelain` empty after. Not run, said in the PR: the plugin gate (nothing under `plugins/` or
  `.claude-plugin/` changes) and the MSRV job (no dependency or edition change).
