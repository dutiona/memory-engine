# S0.3 (#43) — ME bootstrap/backdate path audit

**Status:** DONE (read-only audit + hermetic dry-run). **Date:** 2026-06-14.
**Scope:** `engine/bootstrap.rs`, `bootstrap/{mod,parse,filter,extract,outcome}.rs`,
`store/facts.rs`. **Feeds:** B3 backfill (#53), conflation horizons (S0.2 / #42).

## BLUF

ME's bootstrap path is **idempotent per session**, **backdates `t_created` to the real
historical session time** (so Ebbinghaus decay is computed from when the fact was actually
created), and is **unblocked by design** for B3 — the earlier "ME can't append to an existing
DB" worry was a CLI-wrapper limitation, not an engine one. **Two gaps** matter for a 9-month
backfill and are recommended as ME issues (§5): (a) **no fact-level dedup** — the same fact in
two sessions is stored twice; (b) bootstrap sets **`t_valid = None`** (valid-time is never
populated), which S0.2's `t_valid` horizon sweep must account for.

## 1. Pipeline (`bootstrap/mod.rs`)

```
JSONL → parse → reconstruct turns → classify outcome (full turns)
      → keyword pre-filter (Bug/Decision/Convention/Learning)
      → extract facts (KeywordExtractor, no LLM)
      → ingest marker event + insert facts   [all within one SQLite SAVEPOINT]
```

Per-session atomicity via `SAVEPOINT bootstrap` / `RELEASE` / `ROLLBACK TO`. Outcome is
classified on the **full** turn list _before_ `max_turns` truncation (resolution evidence
lives at the session tail). Bootstrapped facts are **not** added to the HNSW index until the
engine is reopened (index is rebuilt from the DB at open) — acceptable for batch import, but
B3 must reopen (or rebuild) before semantic recall over backfilled facts.

## 3. Implications

- **For S0.2 / #42 (conflation horizons via `t_valid`).** Backfilled facts have `t_valid = None`.
  A horizon sweep keyed on `t_valid` will not see a value on bootstrapped facts — #42 must
  either **set `t_valid` itself** for the conflation conditions, or **sweep on `t_created`**
  (which _is_ backdated and is what the Ebbinghaus recency signal already uses). Recommend
  `t_created` as the horizon axis unless valid-time semantics are specifically under test.
- **For B3 / #53 (9-month backfill).** (a) Idempotency makes re-runs safe (resume-friendly).
  (b) **No dedup** ⇒ recurring facts (e.g. a convention repeated across months of sessions)
  accumulate as duplicates; expect fact volume to scale with _mentions_, not _distinct facts_.
  A consolidation/dedup pass (DreamCycle, or a hash-based merge) should run after backfill.
  (c) Multi-category turns inflate counts (same content, multiple types).

## 4. Dry-run (reproducible, hermetic)

`tests/bootstrap_dryrun.rs` — in-memory engine + zero-vector embedder (no network, no Ollama,
no GPU contention; S0 is build-only). Five synthetic Claude-Code-style sessions backdated
across 2024–2025, one shared convention across two of them. A recording `PersistenceClassifier`
captures every bootstrapped fact's `(content, t_created)`. Asserts: yield > 0; idempotent
re-run (all skipped, 0 new facts); every `t_created` is historical (2024/2025, never `Utc::now()`);
and the shared fact is stored from ≥ 2 distinct session timestamps (no cross-session dedup).

```bash
cargo test --test bootstrap_dryrun -- --nocapture
```

## 5. Recommended ME issues (to file, linked to #43 / #53)

1. **No fact-level dedup on bootstrap insert.** `content_hash` is indexed but not enforced and
   the insert has no `ON CONFLICT`; a 9-month backfill duplicates recurring facts. Decide:
   dedup-on-insert (hash lookup) vs a post-backfill consolidation pass. (Gates B3 quality.)
2. **Bootstrap leaves `t_valid = None`.** Confirm this is intended (valid-time = externally
   asserted knowledge validity, distinct from ingest time) and document it, or have bootstrap
   set `t_valid = candidate.timestamp`. Affects any valid-time-dependent query and S0.2's
   horizon design.
3. **No index on `t_created`.** `t_created` is RFC-3339 text and `facts` has no
   `idx_facts_created` (indices cover `t_expired`, `fact_type`, `(t_valid, t_invalid)`,
   `content_hash`, `scope_id`). A #42 horizon sweep that filters/orders on `t_created` over a
   9-month backfill is a full scan + lexicographic compare — correct (uniform `to_rfc3339()`
   form) but unindexed. Add `idx_facts_created` if the sweep keys on it. (Found by review.)
