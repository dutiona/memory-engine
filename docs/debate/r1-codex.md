1. **Memory Architecture: Hybrid, but not symmetric**
Treat Memori as the **operational memory plane** (hot path) and graph as a **semantic governance plane** (slow path), not co-equal primaries. The assumption that “graph as primary” is better ignores latency and write amplification: every interaction becoming triples/edges will bottleneck agent turn-time and increase ontology fragility. Use Memori (SQLite + FTS5 + vector + decay) for retrieval at inference time, with a graph projection pipeline that asynchronously promotes stable entities/relations (e.g., via GraphThulhu/MCP). Composition: `query -> Memori candidate set -> rerank -> optional graph expansion -> merge`. Keep graph writes behind confidence thresholds + schema validators. GraphRAG works when graph quality is high; most teams underestimate graph entropy. Your 43us Memori reads are a hard strategic advantage. Don’t surrender it to symbolic overhead.

2. **Build vs Compose: Neither fork nor rewrite; carve a thin core**
The fork-vs-rewrite framing is a trap. Forking Panther drags daemon-era decisions you may regret; rewriting from scratch repeats solved integration work (connectors, tool buses, auth, retries). Better: build a **new orchestrator core crate** and import Panther/ZeroClaw patterns as libraries or copied modules with strict boundaries. Use ZeroClaw-style trait contracts for agent loop and tool execution, Rig for model abstraction, rmcp for MCP transport, and isolate adapters (Telegram/Discord/etc.) as optional crates. If you fork, you inherit roadmap coupling; if you rewrite, you inherit schedule risk. Cargo workspace with “hexagonal” ports/adapters gives you selective reuse without governance debt. Principle: preserve tested primitives, discard orchestration assumptions. Measure debt by module ownership and testability, not LOC reused.

3. **MLX vs Ollama: Dual-runtime is correct, but only with strict role separation**
“Pick one” is false economy. You have heterogeneous hardware: Mac Mini M4 (MLX sweet spot), Jetson/PC remote serving (Ollama sweet spot). Use **MLX local fast-path** for interactive cognition and **Ollama network runtime** for portability, model lifecycle, and remote execution. But dual-stack only works if hidden behind a single provider interface (Rig traits + capability registry): token streaming, tool-call schema, context limits, and quantization metadata normalized. Route by policy: low-latency local turn -> MLX; long-context/batch/remote GPU -> Ollama endpoint. Biggest risk isn’t runtime complexity, it’s behavioral drift between engines. Add conformance tests (same prompt, expected tool-call JSON equivalence bands). If you cannot afford that test harness, then choose Ollama only. Otherwise dual is strategically superior.

4. **Nightly “Brain Fine-Tune”: risky objective, wrong granularity**
Nightly full-model fine-tuning for personal memory is usually a category error: you’re pushing episodic facts into parametric weights, causing interference and unverifiable drift. Catastrophic forgetting isn’t a bug you can “schedule around.” Memento-style case retrieval exists precisely to avoid this. Viable middle ground: fine-tune **retrieval and ranking**, not core reasoning weights. Concretely: train a small bi-encoder or late-interaction reranker nightly from accepted memories, feedback labels, and task outcomes; optionally LoRA on a tiny classifier for memory type/importance scoring. Keep backbone frozen. Add memory distillation jobs (summaries, contradiction checks, temporal decay updates) rather than generative fine-tunes. If you insist on tuning generation, do weekly gated LoRA with eval suites and rollback, never blind nightly merges. “Brain model” should mean adaptive retrieval policy, not mutable cognition core.

5. **Autonomy + HITL Escalation: non-blocking escalation as first-class workflow**
Assumption to challenge: “human escalation = blocking step.” It must be modeled as an **asynchronous tool contract** with deadlines, fallback plans, and resumable state. Define an `EscalationTicket` abstraction: `{goal, context_pack, candidate_prompts, expected_output_schema, SLA, fallback_policy}`. Agent submits tickets for Claude/Codex/Gemini human-mediated execution; scheduler continues other goals meanwhile. Use partial-order planning so unresolved escalations gate only dependent tasks. Add tiers: L1 auto-retry/self-heal, L2 deferred human prompt, L3 mandatory approval. Prevent stalling with timeout behaviors: degrade objective, use local model approximation, or park task with reminder cadence. Store tickets and outcomes in memory for future prompt templating. This gives compliance with ToS while preserving autonomy. If escalation isn’t explicit in planner state, you’ll get hidden deadlocks and operator fatigue.
